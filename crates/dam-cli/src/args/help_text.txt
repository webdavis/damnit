dam: about = Track tasks and events, staged and committed like git

dam init: about = Make this folder a project: write .dam.lua and create the project's task
dam init: after_help = It writes .dam.lua, which says where this project's tasks go, and creates
the task that holds that path as a working change when no object holds it yet.
Run again where .dam.lua exists, it changes nothing.
It refuses inside another project's folder.

Examples:
  dam init
  dam init --path work/app

dam revert: after_help = Each field the commit changed goes back to its value before the commit.

It refuses a commit that dam pull made.

  dam revert 1a2b3c4 5d6e7f8
  dam revert 1a2b3c4 --json

dam doctor: about = Read this machine, say what is wrong and how to fix it, and contact nothing
dam doctor: after_help = An error raised in secrets.lua is shown as that file wrote it.
It runs the top-level code of config.lua and secrets.lua and calls no credential function.
It exits 1 when a check finds an issue, and prints the report to stdout either way.
--fix creates the starter config.lua and the store where each is missing, then runs the checks.
It changes no file that exists. With checks named, it creates only what those checks cover.

Examples:
  dam doctor
  dam doctor config
  dam doctor sync
  dam doctor --json
  dam doctor --fix
  dam doctor --fix database
dam doctor checks: help = Run only these checks. Default: every check
dam doctor fix: help = Create the starter config and the store where they are missing
